# تقرير الخطوة 7: مقارنة توقيعات أذكى (SignatureComparer)

**التاريخ:** 2026-11-05
**ملف الاختبارات:** [`core_ai/tests/test_signature_comparer.py`](../test_signature_comparer.py)
**البيئة:** حاوية `ai_web` (Python 3.10، tree-sitter 0.20.4)

## الهدف
بـ Code vs Code، القرار "هالتغيير بيكسر يلي عم يستعملوا الكود أو لا" كان بيعتمد على **بصمة من نص التوقيع**: عدد المعاملات، والأنواع، والإرجاع. وأي فرق بالبصمة كان ينحسب كسر. فإضافة معامل اختياري، متل `fetch(url)` لـ `fetch(url, options = {})`، كانت تنحسب كسر، وهي ما بتكسر ولا استدعاء. هالسبب لحاله طلّع **143 تنبيه** على تعديلات سليمة بـ NPM.

وكمان كاشف إعادة التسمية كان بيطلّع نفس التنبيه مرتين، وبيعتبر أي دالتين إلهن نفس الشكل "إعادة تسمية" حتى لو التنتين لسا موجودين (20 تنبيه وهمي).

## شو تغيّر بالكود
| الملف | التغيير |
|---|---|
| `signature_comparer.py` (جديد) | بيقارن المعاملات وحدة وحدة (قواعد متل AexPy، معدّلة لـ JS/TS)، وكل تغيير إله سبب ومستوى خطر: حرج / تحذير / معلومة |
| `structural_diff.py` | "تغيّر التوقيع" بيستعمل المقارِن، **حتى لو نص التوقيع نفسه** (لأنه النص ما فيه القيم الافتراضية). والتحليل القديم بدون معاملات بيرجع للطريقة القديمة |
| `structural_diff.py` | شلنا المرور العام لكشف إعادة التسمية (`RenameDetector`). الكشف صار جوا الكلاس بس: الجسم نفسه (`body_hash`) يعني إعادة تسمية أكيدة، ودالتين بجسم واسم مختلفين كلياً يعني حذف وإضافة. وإعادة التسمية صارت تنحسب **كسر** (RENAMED / حرج)، لأنه الاستدعاءات بالاسم القديم بتفشل |
| `tree_sitter_processor.py` | قراءة معاملات TypeScript: النوع، والقيمة الافتراضية، و `b?` (يعني default = `undefined`)، و `...rest`، و `{a, b}`. وبـ JavaScript صارت تنقرا كمان `({a, b}) =>` و `x => x` |
| `evaluation/harness/llm_recorder.py` | حد tokens لكل موديل: `cohere/north-mini-code:free` بياخد 16000، لأنه "بيفكّر" قبل ما يجاوب، وبـ 4000 كان يرجّع جواب فاضي |

نص التوقيع القديم (`signature`) ما تغيّر حرف، والنسخة المجمّدة ما انلمست.
