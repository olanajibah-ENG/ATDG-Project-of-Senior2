# حالة المهمة بـ UPM، وتنظيف مشاريع demo3 الفاضية

التاريخ: 19/11/2026

## 1. حالة المهمة: `unknown` و `expired` بدل `pending` المضلّل

### المشكلة

`GET /api/upm/tasks/<id>/` كان يرجّع `pending` "Task is waiting to be processed" لمهام رفع خلصت من يومين.
Celery بيقول PENDING لأي id ما عنده نتيجتها، وهي 3 حالات بتطلع متل بعض:

- مهمة لسا بالـ queue (هي بس pending فعلاً).
- id عمره ما انبعت.
- مهمة خلصت ونتيجتها انمسحت (Celery بيحتفظ بالنتيجة يوم واحد).

### الحل

- ملف جديد `UPM_Project/core_upm/task_registry.py`: كل مهمة بيبعتها UPM بينسجّل الـ id تبعها مع الوقت، بنفس الـ Redis
  تبع النتائج (`upm:task-sent:<id>`)، لمدة 30 يوم. بيصير عن طريق إشارة Celery `after_task_publish`،
  فبيشمل كل المهام (الرفع و GitHub) بدون ما نعدّل أماكن الإرسال.
- `core_upm/apps.py`: ربط الإشارة بـ `ready()`.
- `core_upm/views/task_status_view.py`، فرع PENDING:

| الحالة | الجواب |
|---|---|
| ما في تسجيل للـ id | **404** `unknown` |
| في تسجيل وصار إلو أكتر من يوم | **410** `expired`: "The task ran, but its result is no longer kept" |
| في تسجيل وجديد | `pending` متل قبل |
| Redis ما جاوب | `pending` متل قبل (ما منكسر شي) |

وإذا Redis ما جاوب وقت التسجيل، المهمة بتنبعت عادي.

الفرونت ما بيستعمل هالرابط (عنده رابط حالة لخدمة الـ AI)، فما تأثّر.

### التجربة

| الطلب | الجواب |
|---|---|
| مهمة الرفع الأولى تبع 17/11 (`05841d28-...`) | **404** `unknown` (انبعتت قبل التسجيل ونتيجتها انمسحت) |
| id ما انبعت أبداً | **404** `unknown` |
| مهمة جديدة (zip بدون `demo/`، انرفضت) | التسجيل موجود بـ Redis، والجواب `rejected` متل البند 6 |
| تسجيل عمره يومين لمهمة ما إلها نتيجة | **410** `expired` (انمسح التسجيل التجريبي بعدها) |

ملاحظة: الرفع المرفوض بهالتجربة ما عمل نسخة. demo3 لسا 8 نسخ.

## 2. تنظيف مشاريع demo3 الفاضية

لما رجعت بعتّ طلبات Postman، طلب "إنشاء مشروع" عمل 3 مشاريع `demo3` جداد. الرفع راح عالمشروع القديم،
لأنو الـ `project_id` مكتوب بالطلب، فضلّوا فاضيين.

**قبل الحذف تأكدنا إنهن فاضيين:**

| المشروع | الصاحب | انعمل (UTC) | UPM: نسخ / مجلدات / ملفات / GitHub | خدمة الـ AI: ملفات / نسخ / test jobs |
|---|---|---|---|---|
| `c915a90e-...` | user3 | 19:36:16 | 0 / 0 / 0 / 0 | 0 / 0 / 0 |
| `12582669-...` | user3 | 19:40:53 | 0 / 0 / 0 / 0 | 0 / 0 / 0 |
| `3526a08d-...` | user3 | 19:41:32 | 0 / 0 / 0 / 0 | 0 / 0 / 0 |

**الحذف:** بدالة UPM نفسها (`ProjectService.delete_project`، بتتأكد إنو المستخدم صاحب المشروع)،
من جوّا الـ container. ما استعملنا رابط الحذف بالـ API لأنو بيبعت إيميل "project deleted" لصاحب الحساب.

**بعد الحذف:** ضل مشروع `demo3` واحد، `c0e34dfa-...`، بـ 8 نسخ، ما انلمس.
