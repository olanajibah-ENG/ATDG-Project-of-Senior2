بـ Code vs Code، وما بتحتاج ذكاء اصطناعي، فمنقيسها على كل بيانات NPM ببلاش. وآخر الصفحة في خطة "داتا أكبر" يلي طلبها الدكتور.

الخطوة 7 بتعالج أكبر سبب (التوقيع)، وسبب إعادة التسمية. الحذف إله الخطوة 10 (الدوال الخاصة متل _helper ما بتكسر حدا).

2. ليش النظام هلق بيغلط

هلق، القرار "بيكسر أو لا" بيعتمد على بصمة مبنية من نص التوقيع: عدد المعاملات، وأنواعهم، ونوع الإرجاع. إذا البصمة تغيّرت بأي شكل، بيعتبره كسر.

// قبل
function fetch(url)
// بعد
function fetch(url, options = {})

عدد المعاملات تغيّر من 1 لـ 2، فالبصمة تغيّرت، فالنظام بيقول كسر. بس فعلياً كل يلي كانوا يستدعوا fetch(url) لسا شغّالين، لأنه المعامل الجديد إله قيمة افتراضية. يعني ما بيكسر.

ومشكلتين بكاشف إعادة التسمية (لقيناهم بالخطوة 2)

  1. تكرار: في مكانين بالكود بيكشفوا إعادة التسمية، وكل واحد بيطلّع تنبيه لنفس الشي.
  2. إعادة تسمية وهمية: الكاشف التاني بيقارن البصمات بكل الملف. فأي دالتين إلهن نفس الشكل (مثلاً بدون معاملات) واسمهن مختلف بيعتبرهن "إعادة تسمية"، حتى لو التنتين لسا موجودين. وهاد سبب الـ 20 تنبيه.

3. الحل: مقارِن توقيعات جديد

بدل نص التوقيع، منقارن المعاملات نفسها يلي صرنا نقراها بالخطوة 1 (الاسم، والنوع، والقيمة الافتراضية، والنوع: عادي أو ...rest). والقواعد مبنية على طريقة AexPy، ومعدّلة لـ JavaScript/TypeScript:

إضافة معامل اختياري أو إله قيمة افتراضية بالآخرf(a) لـ f(a, b = 1) أو f(a, b?)ما بيكسر

كل تغيير بيطلع مع سببه بالوصف (مثلاً "انضاف معامل إجباري b")، ومستوى خطر من الحقل يلي ضفناه بالخطوة 2: حرج / تحذير / معلومة. وبس "حرج" بينحسب كسر.

تصليح كاشف إعادة التسمية

  • منخلّي مكان واحد بس بيكشف إعادة التسمية، وجوا نفس الكلاس.
  • إعادة التسمية بتنحسب بس بين دالة انحذفت ودالة انضافت، مش بين دوال لسا موجودة.
  • منستعمل بصمة جسم الدالة يلي ضفناها بالخطوة 1: إذا الجسم نفسه بالزبط والاسم تغيّر، هي إعادة تسمية أكيدة.

شغلة لازم نكمّلها

قراءة معاملات TypeScript لسا ما بتسجّل إذا المعامل اختياري (b?) أو إله قيمة افتراضية (b: number = 1). منكمّلها بهالخطوة، لأنه القواعد فوق بتعتمد عليها.

5. كيف منقيسها

  • منعيد قياس كل NPM (تطوير واختبار) بدون ذكاء اصطناعي، ببلاش، ومنقارن مع أرقام الأساس.
  • المتوقّع: الـ Specificity (السكوت عن السليم) يطلع فوق 0.82، والـ Recall يضل قريب من 0.35.
  • منشوف كمان الكشف حسب النوع: "تغيير التوقيع" (130 تعديل) و"async/sync" (21 تعديل) لازم يتحسّنوا.
  • بحلّل الحالات يلي تغيّر قرارها بقسم التطوير بس، متل ما متفقين.
