1. الفكرة وطريقة الشغل

المشروع فيه قسمين لكشف المشاكل:

  • Code vs Doc: هل التوثيق بيوصف الكود صح؟ مثلاً التوثيق بيقول "بترمي خطأ إذا القيمة فاضية"، والكود ما بيعمل هيك.
  • Code vs Code: بين نسختين من الكود، شو تغيّر؟ وهل التغيير بيكسر يلي عم يستعملوا الكود؟

عم نحسّن القسمين حسب 3 خطط مبنية على أوراق بحثية: DocPrism و METAMON للتوثيق، و AexPy و NPM و Safer Builders للكود، وخطة ثالثة لإثبات الدقة.

قواعد الشغل:

  • كل خطوة بتنشرح قبل ما تتطبّق، ومنطبّقها بعد الموافقة بس.
  • كل خطوة إلها اختبارات، وتقرير اختبارات مكتوب.
  • منقيس على بيانات الأوراق نفسها، مش على بيانات عملناها نحنا. وبتوجيه الدكتور: ورقة وحدة لكل قسم، يعني CASCADE للتوثيق و NPM للكود.
  • البيانات مقسومة لتطوير (منفتح أخطاءه ومنتعلّم منه) واختبار (أرقام بس)، لحتى ما نغش.
  • كل الشغل على الحد المجاني للذكاء الاصطناعي، يعني 50 طلب باليوم.

5. Code vs Doc: الخطوات 1 لـ 6

الخطوةشو عملناليش، وشو تغيّر
1معلومات كاملة عن كل دالةكان النظام بيعرف الاسم والتوقيع بس. صار يقرا الجسم، والمعاملات (الاسم، والنوع، والقيمة الافتراضية)، ونوع الإرجاع، والتوثيق الداخلي، و async، والـ constructors، وأرقام الأسطر، وبصمة للجسم بتتجاهل التعليقات والمسافات
2بنية البياناتتصنيفات DocPrism: تناقض مباشر (Direct_Mismatch)، ووعد زيادة (Over_Promise)، ونقص بالتوثيق (Under_Promise). ومستويات خطر، وقرار التغيير، وإعادة التسمية. وصلّحنا خطأ كان يوقّف كل Code vs Code (القسم 9)
3تقسيم التوثيق وربط كل جزء بدالتهبدل ما ينبعت التوثيق كله دفعة وحدة، كل دالة بتنفحص مع الجزء يلي بيحكي عنها
3بالدوال يلي برّا الكلاساتكان النظام ما يشوفها أبداً، وهي نص بيانات DocPrism، وكتير منتشرة بـ JavaScript. صارت تظهر ككلاس وهمي <module>، والمخطط بالواجهة ما تغيّر
4سؤال جديد للذكاء الاصطناعيمتل DocPrism: ملخّص للكود وملخّص للتوثيق، و3 أسئلة (شو بالتوثيق مش منفّذ؟ شو متناقض؟ شو بالكود مش موثّق؟). والموديل لازم ينسخ الجملة من التوثيق والسطر من الكود كما هم، ويعطي درجة ثقة
5محلّل التوثيق الجديدإعادة المحاولة 3 مرات. ومنرمي أي جواب جملته أو سطره مش موجود فعلاً (اختراع)، وعتبة ثقة 0.7، ومنشيل التكرار. و"النقص بالتوثيق" ما بينعرض للمستخدم (متل DocPrism)، وإذا فشل الطلب ما بيوقع النظام
6ربط المحلّل بالنظامصار يشتغل تلقائياً. وشلنا الفحص القديم للتوقيع، لأنه كان سبب كل الإنذارات الكاذبة، وصار "غير موثّق" إحصائية مش تنبيه. والفحوصات الثابتة للتوثيق المنظّم ضلّت

7. Code vs Code: الخطوات 7 لـ 10

الخطوة 7: مقارنة التوقيعات معامل معامل

المشكلة: القرار "بيكسر أو لا" كان بيعتمد على بصمة من نص التوقيع، وأي فرق يعني كسر. فإضافة معامل اختياري (fetch(url) لـ fetch(url, options = {})) كانت كسر، وهاد كان أكبر سبب للإنذارات الكاذبة (143 تنبيه على تعديلات سليمة). وكاشف إعادة التسمية كان يكرر التنبيه، ويعتبر دالتين لسا موجودين "إعادة تسمية" (20 تنبيه).

شو عملنا:

  • مقارِن جديد بقواعد متل AexPy:
    • ما بيكسر: معامل اختياري انضاف، أو معامل صار اختياري، أو اسم معامل تغيّر بـ JS/TS/Java، أو نوع معامل صار أوسع، أو الإرجاع صار أضيق.
    • بيكسر: معامل إجباري انضاف، أو انشال، أو صار إجباري، أو الترتيب أو النوع تغيّر، أو الإرجاع صار أوسع (A لـ A | null)، أو الدالة صارت async، أو صارت خاصة.
  • المقارنة بتصير حتى لو نص التوقيع نفسه، لأنه النص ما فيه القيم الافتراضية.
  • إعادة التسمية صارت تنكشف جوا الكلاس بس، وببصمة الجسم. بتطلع مرة وحدة، وبتنحسب كسر، لأنه الاستدعاءات بالاسم القديم بتفشل.
  • قراءة معاملات TypeScript كاملة: قبل كانت الأنواع والقيم الافتراضية تضيع، و ...rest و {a, b} يختفوا كلياً.

الخطوة 8: مقارنة أجسام الدوال

ثلثين بيانات NPM تغييرات سلوكية، والنظام ما كان يقارن الأجسام أبداً. صار لكل دالة 3 أشياء: الحالة (ما تغيّر، أو تغيّر، أو غير معروف)، والفرق سطر سطر بدون تعليقات، و8 إشارات سلوكية مربوطة بأنواع NPM:

  • return تغيّر (change return).
  • throw انضاف أو انشال (error handling).
  • قيمة ثابتة تغيّرت (change default).
  • قراءة الخيارات تغيّرت (option handling).
  • شرط تغيّر، أو استدعاء انضاف أو انشال.

ما بتطلّع تنبيهات، بس معلومات للخطوات الجاية.

الخطوة 9: تصنيف التغيير لكل دالة

قرار واحد لكل دالة من التوقيع والجسم:

  • ما تغيّر.
  • بنيوي بس: الخطوة 7 بتقرّر.
  • بنيوي وسلوكي: بينبعت للذكاء الاصطناعي.
  • مرشّح سلوكي: بينبعت للذكاء الاصطناعي.

وكمان فلترة التغييرات التافهة (تسجيل أو طباعة بس، نص رسالة خطأ بس، اسم متغيّر محلي بس)، ودرجة أهمية من الإشارات، بأوزان محسوبة على قسم التطوير بس.

الخطوة 10: مستوى الخطر

  • كل تنبيه إله مستوى: حرج، أو تحذير، أو معلومة.
  • الأعضاء الخاصين معلومة بس، ومش كسر (متل AexPy). هدول يلي اسمهم بيبلّش بـ _ (مش __x__) أو #، أو مكتوب عليهم private أو protected.
  • JavaScript و TypeScript: صار النظام يقرا شو عليه export بكل ملف. والشي يلي ما عليه export بنفس الملف بياخد "تحذير" مع ملاحظة إنه ممكن يكون داخلي، بس بيضل كسر.

قياس صغير مع الذكاء الاصطناعي (بعد الخطوة 6)

22 تعديل من التطوير، كل واحد فيه ملف واحد (17 بيكسر و 5 سليم). القديم كشف 3 من 17، والحالي 5 من 17، والتنين بدون ولا إنذار كاذب. بس الذكاء الاصطناعي لحاله ما كشف ولا تغيير سلوكي، لأنه التحليل الدلالي القديم بيوصله أسماء الدوال بس.

شو تحسّن
  • الكشف طلع من 0.22 لـ 0.38 (بقسم الاختبار). انكشف 173 تعديل بيكسر زيادة.
  • الخطوة 3ب لحالها جابت أكبر قفزة: صار النظام يشوف الدوال يلي برّا الكلاسات، وهي الشكل الأشيع بـ JavaScript.
  • الخطوة 7 زادت الكشف بدون ثمن: انكشف 40 تعديل زيادة، وما زادت الإنذارات الكاذبة. وانكشفت تغييرات ما كانت تبيّن بنص التوقيع أبداً.
  • الخطوة 10 نزّلت إنذارين كاذبين، وصار كل تنبيه إله مستوى خطر وسبب.
شو ما تحسّن، وليش
  • الـ Specificity لسا 0.83، أقل من القديم (0.89)، لأنه صرنا نشوف كود أكتر بكتير.
  • التغييرات السلوكية (ثلثين البيانات) لسا تقريباً ما بتنكشف إلا بالصدفة (0.28). وهاد شغل الخطوة 11.
  • سقف الكشف السلوكي حوالي 0.70: بـ 30% منها التغيير مش جوا دالة منشوفها.
  • تغيّر الجسم لحاله ما بيفرّق: 58% من السليم كمان فيه جسم تغيّر.
  • الإشارات ودرجة الأهمية ضعيفة لحالها (AUC 0.62). يعني القرار بيحتاج الذكاء الاصطناعي.

11. حدود النتائج

  • عينات التطوير صغيرة: 25 زوج بـ CASCADE مع الذكاء الاصطناعي، و22 تعديل بـ NPM مع الذكاء الاصطناعي.
  • قسم اختبار CASCADE لسا ما انقاس مع الذكاء الاصطناعي، والقياس الكامل بالموديل الجديد عم يصير.
  • الأمثلة السليمة بـ NPM نحنا جبناها، ومش موسومة من المؤلفين. ولما فتحنا الإنذارات الكاذبة بالتطوير، لقينا بكتير منها تغيير API حقيقي ما انكتب إنه بيكسر. يعني الـ Specificity الحقيقية ممكن تكون أحسن.
  • JavaScript: منحلّل بس الملفات يلي تغيّرت، فما منعرف إذا الشي عليه export من ملف تاني (index.ts).
  • موديل مجاني صغير واحد، والأوراق استعملت موديلات أقوى.
  • LLM-S بيكشف أكتر منّا (0.54–0.67)، بس بإنذارات كاذبة أكتر بكتير. ميزتنا هي إنذارات أقل مع كشف منيح، مش أعلى كشف.
